# Windows companion interface

Mode: Operate. Aesthetic: Japandi utility, using a native Windows shell. Warm neutral surfaces, a restrained forest-green accent, no texture, shadows, gradients or decorative motion. Segoe UI is a deliberate native-platform exception to the generic web-font rule; regular and semibold only.

## Reference decision, September 30

Mobbin was requested and attempted in Chrome at https://mobbin.com/browse/web/apps. The initial MCP client needed OAuth reauthorization. Reconnected successfully with `codex mcp login mobbin`; the callable search tool then returned “Mobbin MCP requires a paid plan.” The user then signed into the browser library, which provided access to screens; MCP continued returning its plan gate even after another authorization refresh. No plan change was made.

Mobbin cross-check: [Linear notifications](https://mobbin.com/screens/a0ffb988-a36b-4f3a-b4f6-b14310088981), actually viewed after browser sign-in, supports grouped setting rows, label/help hierarchy and right-aligned toggles. [Front notifications](https://mobbin.com/screens/3e800980-2838-4ce2-a5ba-95994c99c3ee) was reviewed but its multicolumn controls and side help panel were rejected as too complex for this utility. Raycast remains the structural backbone; Linear reinforces the row treatment.

Structural backbone: the account and launcher settings screenshots actually viewed on https://manual.raycast.com/settings. Borrow the persistent quiet sidebar, grouped preference rows, right-aligned controls and restrained help hierarchy. Do not copy its branding, account flow, dark palette, or AI-provider complexity. This is a focused refinement of the existing seven-tab Windows app, not a new product flow.

## Tokens and behavior

- Surface #FAFBF9; sidebar #F0F3EE; ink #243A33; secondary #627169; border #DEE5DF; accent #356B55; selection #DCEAE1.
- Sidebar 190 DIP; content padding 32 horizontal / 28 vertical. Spacing 4/8/12/16/24/32 DIP. Body 14, help 13, navigation 14, main title 28. Buttons at least 36 DIP. Rounded controls 6 DIP, switch 11 DIP.
- Windows controls remain WPF controls with native automation peers and keyboard behavior. Setting rows are named checkboxes rendered as switches; shortcut modifiers keep checkboxes. High contrast uses native templates and system colors instead of the custom theme.
- Seven destinations: Dictation, Shortcuts, Sound, Privacy, Models, History, Vocabulary. Most preferences save immediately; shortcut edits apply together because registration can fail. Inline status and rollback on save failure. Close hides to tray; Quit is explicit.
- History is a searchable list plus selectable transcript detail; vocabulary is a list and inline editor. One window plus native file dialogs/destructive confirmation is the nesting limit.
- Bottom-center recording panel uses charcoal #182322, mint #E5F5EF / #94D9BC, matching dark buttons and content-sized height. It never activates or takes the dictation target. Escape and shortcut controls remain available.

## Sound palette

Soft (default): rounded 130 ms tap. Wood: dry 90 ms knock. Glass: light 220 ms note. Stop uses a lower pitch so actions remain distinguishable. All three use fixed pitches, smooth attacks/tails and peak amplitude 0.19 before app gain. Original cues remain as Classic. Original waveforms are generated by `scripts/generate-sounds.py`; no borrowed OS audio.

Saved volume and custom imports survive upgrade. Custom imports override the selected preset for their respective cue until “Use selected style” is chosen. Preview works with recording sounds disabled. Nothing changes the system mixer. Existing sound-off preferences remain off.

## Verification

Mac compilation is not visual acceptance. Native Windows smoke captures all seven sections, scroll bottoms, the smallest supported window and the nonactivating overlay. It exercises every preset selection and decodes every bundled sound, alongside shortcut conflict rollback and unsafe-target refusal. User listening on the actual speakers remains the subjective sound acceptance check.
